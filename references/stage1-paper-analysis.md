# 階段 1：論文深度解析

## 目標

規劃任何投影片之前，先把研究「說了什麼、證據到哪裡、哪裡沒說」整理清楚。後面每一頁投影片和每一句講稿，都要能追溯回這份解析。

## 閱讀順序建議

1. **研討會版**：摘要 → 結論 → 所有圖表 → 方法 → 結果與討論 → 前言與文獻回顧。先看結論和圖表，可以較快抓到故事線，再回頭確認方法細節。
2. **完整研究**：只找研討會版沒有交代清楚的背景、方法細節和機制說明，以及兩版之間的差異。

---

## 十個項目的寫法

以下每一項中的每條陳述，都要附上證據標籤（【實測】【文獻】【作者推論】【推算】【未交代】【建議】）和出處。

### 1. 研究背景與實際應用情境

- **要回答**：實際的工程或產業情境是什麼？問題會造成什麼代價（安全、成本、壽命或效率）？為什麼這個問題現在值得研究？
- **到哪裡找**：前言的前幾段，以及完整研究的緒論。
- **注意**：關於代價或規模的數字，必須有出處。論文沒有給數字，就不要補。

### 2. 現有文獻已知什麼、還有哪些缺口

用表格整理：

| 主題 | 代表文獻 | 已知結論 | 限制或未解決之處 | 出處 |
|---|---|---|---|---|

- 缺口要分成兩種：
  - 作者在論文中明確寫出的缺口，引用原文並附頁碼。
  - 從文獻整理表推論出來的缺口，標【建議】。

### 3. 缺口如何轉化成研究目的與研究問題

用對應表整理：

| 缺口 G | 研究目的 O | 研究問題 RQ | 回答它的實驗或圖表 |
|---|---|---|---|

- 論文沒有明列研究問題時，從研究目的和實驗反推，並標【建議】。
- 如果某個目的沒有任何實驗回答它，或某個實驗沒有對應到任何目的，要明確指出來。這兩種情況在研討會上常被追問。

### 4. 核心故事線與關鍵訊息

- **一句話故事線**，可套用這個句型：「在〈情境〉中，〈問題〉；過去研究〈已知〉，但〈缺口〉；本研究以〈策略〉，發現〈主要結果〉，因此〈工程意義〉。」
- **2～3 個關鍵訊息**：每個訊息寫成一句話，讓聽眾離場時能複述，並附上支撐它的證據（圖表號）和證據等級。
- 只有【實測】支撐的結果，才能當作關鍵訊息。推論可以作為延伸討論，但不能當主結論，否則問答時很難守住。

### 5. 實驗設計

| 項目 | 內容 | 出處 |
|---|---|---|
| 對應的研究問題 | | |
| 因子與水準（含單位） | | |
| 固定條件 | | |
| 試體／樣本數與重複次數 | | |
| 對照組或基準 | | |
| 量測項目、方法、儀器或標準 | | |
| 量測時間點 | | |
| 分析方法（統計或模型） | | |

- 論文沒有交代的格子，寫【未交代】，不要留白，也不要自行補上。
- 若採用實驗設計法（如田口法、全因子設計、反應曲面法），寫出設計名稱和直交表或實驗組數（run 數）。
- 研討會版和完整研究的設計不同時，以研討會版為準，差異另外列出。

### 6. 主要圖表與數據

| 圖表 | 頁碼 | 呈現什麼（軸、組別、單位） | 回答哪個 RQ | 關鍵數值或趨勢 | 證據等級 | 建議用途（主講／備用／不用） |
|---|---|---|---|---|---|---|

- 關鍵數值照論文原文抄錄；從圖上讀出的數值，要標「估讀」。
- 確認誤差棒代表什麼（SD、SE、信賴區間或全距），以及樣本數 n。論文沒說明的話，標【未交代】。

### 7. 統計顯著性、效應量與工程意義

依論文**實際使用**的方法說明，不要換成另一套方法來解釋。

- **方法**：用了什麼方法、檢定什麼假設、顯著水準設多少。
- **統計量**：列出論文報告的統計量（F、p、R²、貢獻率、S/N 比、信賴區間等）和出處。
- **效應量**：
  - 論文有報告，就照錄並解釋。
  - 論文沒報告，就寫【未交代】。
  - 可以用論文已報告的平均值計算相對變化（%），作為「工程上的變化幅度」，標【推算】並附算式。這不是統計上的效應量，講稿中不要這樣稱呼。
- **工程意義**：差異是否超過規範門檻、設計值、量測誤差，或實務上感受得到的程度？
  - 只有論文提供了判讀基準，才下這個判斷。
  - 沒有基準時，寫明「論文未提供工程判讀基準」。
- **常見誤讀**：統計上顯著，不代表工程上重要；不顯著，也不代表沒有影響，可能只是樣本數不足。若論文的樣本數偏小，用【建議】提醒檢定力有限。

### 8. 核心機制、交互作用與其他重要概念

| 概念 | 在本研究中的角色（動機／假設／設計／解釋） | 證據等級 | 是否納入原始設計 | 本研究有無直接量測證據 | 出處 |
|---|---|---|---|---|---|

判斷「是否納入原始設計」：

- **【設計內】**：在研究目的、假設或實驗設計中就已出現，例如把交互作用項放進實驗設計，或特地安排量測來觀察該機制。
- **【事後解釋】**：只在結果討論中出現，用來解釋觀察到的現象。

這個判斷會直接影響簡報怎麼說：

- 【設計內】的概念，可以放在動機和研究策略中鋪陳。
- 【事後解釋】的概念，應該放在結果解讀的段落，用「可能的解釋」來說，不要在簡報中改寫成「我們一開始就假設……」。
- 【文獻】機制本來就是已知的，可以用來支撐研究動機。但本研究結果的成因解釋，要依實際證據等級來表達。

### 9. 貢獻、工程決策應用、適用範圍與限制

- **貢獻**：本研究新增了什麼知識、方法或工具（要對應到第 2 項的缺口）。
- **工程決策應用**：工程師可以根據這個結果做什麼決定、在什麼條件下適用。論文明說的和【建議】要分開列。
- **適用範圍**：材料、參數範圍、環境、尺度。超出試驗水準的外推，要明講論文不支持。
- **限制**：作者自己陳述的限制（附出處），和解析時看出的限制（標【建議】）分開列。
- **新指標或公式**（若有）：

| 項目 | 內容 |
|---|---|
| 定義 | |
| 計算式（含變數定義與單位） | |
| 參考基準（和什麼比較、基準值的來源） | |
| 判讀方式（越大越好？有沒有門檻值或分級？） | |
| 本研究的實際數值範例 | |
| 驗證情形與適用限制 | |

缺哪一項就標【未交代】。

### 10. 研討會可能被追問的重點

列出 8～12 題，涵蓋方法、統計、機制、應用、限制，以及和其他文獻的比較。

| 問題 | 類型 | 論文依據（出處） | 可回答程度 | 建議回答要點 | 需要備用頁？ |
|---|---|---|---|---|---|

- 可回答程度分三級：**完整**、**部分**、**論文無法回答**。
- 遇到「論文無法回答」的問題，建議一個誠實的回應方式並標【建議】，例如：「這部分本研究沒有量測，是後續研究的方向。」
